# My 4418 + Announcements V1

Local only. Review `supabase/migrations/202609120005_hub_dashboard_announcements.sql`,
then manually run that file once in the existing shared Supabase project's SQL
editor after the existing Attendance, Inventory, Pit, hardened Finance and Team
Management migrations. Do not rerun those earlier migrations. Deploy Hub only after
migration review/application and an authenticated check with a student and mentor.
No DNS, secrets, email configuration, or other app deployment is required.

The Systems grid remains unchanged. My 4418 follows it, then Announcements,
Team Resources, and mentor/admin Administration. Existing Attendance sign-in is
reused. The announcement manager lives at `#announcements` and is linked for
mentors/admins from the dashboard. No external integrations or notification sends.

`team_dashboard_context()` is SECURITY INVOKER, with no caller-supplied user ID.
Existing table permissions and RLS apply to every read. It returns personal
attendance and the caller's latest five POs. Leadership receives aggregate
attendance, active-event Pit readiness, and stock attention; Finance actions follow
existing position/capability checks and distinct-person/current-revision rules.
Normal self-approval and emergency override are never suggested as dashboard actions.
Raw histories, notice explanations, and other students' personal records are omitted.

Attendance percentage matches the existing app: finalized required records only,
excluding excused/not-required; present, late and left early count as attended.
Strikes are the sum of unrescinded records; leadership action begins at three.
Pit includes unresolved deferred issues and treats HIGH/ROBOT DOWN as blocking,
matching existing readiness. Inventory uses its existing maintained item quantity
and minimum, with zero out-of-stock and positive quantity at/below minimum low.
Dashboard numbers are snapshots; Refresh updates them. Announcement expiration
is also filtered client-side every 30 seconds. Source access/configuration failures
show an error rather than fabricate zero counts. Auth and RPC waits are bounded.

The only new table is `team_announcements`. Active global announcements reach all
active users; area targets reach that area and active mentors/admins. Normal views
omit expired/inactive entries; management can review them. The mutation RPC is
mentor/admin-only, derives creator server-side, validates content and area, and
uses a version check to prevent overwriting concurrent edits. There is no direct
client insert/update/delete permission. Body content is rendered as plain text.
No existing policies, schemas, workflow functions, or frontend auth files change.

Validation: `npm run build` and `npm test`. New database tests use local PGlite;
UI tests use mocked APIs at desktop/phone widths, including authorization,
announcements, empty/error states, sign-out, and navigation. No production writes.
