# Sponsor & Outreach: frontend review

This is a local, bounded internal Hub workspace. It is not deployed and contains no runtime demonstration data, real contact import, outbound messaging, public sponsor page, payments, or accounting. The user authorized regular student/lead participation and team-wide visibility of sponsor business contacts; production rollout remains held. See [the backend contract](sponsor-outreach-v1.md) for the model, privileges, concurrency rules, and rollout prerequisites.

## Surfaces

- `#outreach`: selected-season relationship metrics, scheduled follow-ups due, sponsor/contact search, relationship-stage filter, and optional archive browsing. Organization and individual sponsor profiles are global; relationships, conversations, commitments, and recognition belong to the selected Finance season.
- `#outreach/<UUID>`: shared profile/contact details, season owner and next follow-up, and append-only conversation history. Mentor/admin views additionally include cash/in-kind commitments and promised/fulfilled/waived logo, recognition, and thank-you obligations. No new Hub account or implicit team position is created for a sponsor/contact.
- Native modal forms provide validation, saving/error/conflict states, explicit cancel, keyboard dismissal, and focus handling. Unavailable owners require an explicit replacement or Unassigned choice rather than silently clearing responsibility. Archived organizations and closed seasons display retained history with dependent changes disabled. Archive/reactivate controls are intentionally not part of this first UI.
- Finance income linking selects an existing same-season income record. Received totals sum only linked Finance rows currently marked received; expected or canceled income never counts. “No received income linked” does not assert that a sponsor has paid nothing. Logo/thank-you fulfillment never changes a pledge or Finance receipt state. Finance navigation opens the existing verified `https://finance.frc4418.org/#income` workspace, not an invented per-record route. The selected season is visible beside it. V1 has no unlink/reassignment UI; a mistaken association needs a separately reviewed correction, and linking never changes Finance data.

## Student coordination and mentor oversight

Active students and leads see Sponsor & Outreach navigation and all sponsor names, websites, and business contacts, including unassigned profiles. These visibility rights never grant assignment or mutation authority. Explicit server-provided row capabilities control profile/contact edits, adding contacts, starting a season relationship, and recording activity. Students edit their own profile/contact records and work on relationships they created or that a mentor assigned to them; mentor/admin oversight and assignments remain available. A mentor-created assignment revoked while a form is open produces a denied save, closes the stale editor, and reloads the current read-only view. The UI does not infer authority from the visible list of team names.

“Add prospect” atomically creates a profile and a selected-season relationship owned by the student. The reviewed profile UUID and engagement UUID are sent in one existing save RPC with one recovery request UUID. Students cannot use this flow to self-assign an existing sponsor. They can then add a business contact and manually record an email already sent. There is no email delivery action, outbound queue, or automatic follow-up. Shared timeline entries explicitly say “Manually recorded”; date/channel metadata is not proof of delivery.

Students see shared author/date/channel/contact metadata, their own conversation details, and an explicit restricted-content label for another author's details. Mentor/admin viewers see all details. Conversation entries remain append-only; no student's view includes an edit-other-author action. Profile, contact, and engagement private notes arrive as null with explicit redaction flags, never as empty editable fields. Student forms hide these fields and omit notes, archive state, ownership, and authorship from their edit payloads so the server preserves protected values.

Student views show shared profile counts, their actionable scheduled follow-ups, and last manually recorded contact dates. Pledge/recognition forms, financial navigation, commitment tabs, and financial totals are absent; restricted financial data is never displayed as zero commitments or $0 received. Mentor screens retain the original financial distinctions and existing Finance capability checks.

## Privacy and interrupted work

The screen requires a complete contract-version-2 response with the exact current actor, explicit viewer and per-record capabilities, validated record shapes, and consistent organization/engagement/season references. No fallback sample data or partial response is shown when the backend is absent, permission is denied, or the response is malformed. Student financial arrays must all be empty with financials_redacted=true; every private-note flag must agree with a null value, and conversation-body visibility must match mentor access or exact authorship. Finance projections must also be empty whenever the separate Finance capability is absent. A contradictory projection fails closed. Authorized profile/contact data and form drafts are held only in the active view.

Requests use the existing Hub SSO client. They pin the reviewed actor's token, carry `expected_actor` on writes/recovery, disable PostgREST retries, and remain bound to an uninterrupted route/account/editor scope through SSO waits and response processing. Account change, Close, unmount, route departure, season change, and reload discard the active form/view. Late responses cannot repopulate a different view or close a new editor.

Immediately before a write is dispatched, an opaque receipt is recorded in this tab's session storage: actor UUID, request UUID, record UUID, operation type, and expected version. No contact fields, draft text, amounts, passwords, or tokens are persisted. Receipts survive form dismissal, route/season changes, and page reload. They are shown only for their exact actor after a newly authorized context load. Further changes for that actor pause while a previous outcome is uncertain.

“Check previous save” is read-only and preserves the original UUID. `not_found` stays inconclusive. An `applied` response must match the retained record/version before unlocking edits; Finance link responses have the separate fixed version-1 link contract. The explicit “Cancel unconfirmed change” action uses the original UUID and the backend cancellation tombstone. It either returns the existing applied result or durably prevents that request from applying; it never deletes an already-saved record. Cancellation timeout, account switch, or route departure keeps the original receipt for later status/cancel recovery. No operation is automatically retried or replaced.

If session storage is blocked, recovery remains in this tab's memory and the UI tells the user to keep the tab open. Recovery cannot survive closing that tab or a full reload in that browser state. Clearing browser data also loses local receipt identifiers; server audit and idempotency records remain authoritative.

## Local verification

- `tests/outreach-model.spec.ts`: pure model, React server-rendering, transport/race, and receipt recovery tests. Uses esbuild and an entirely synthetic injectable transport, with no browser or network listener required. Cases cover strict route/capability parsing, cross-record/season/date consistency, private Finance gating, actual linked received amounts, archived/closed display, unavailable owners, actor switch during SSO waits, route abandonment, malformed results, canceled/applied reconciliation, exact request/version matching, and opaque reload persistence. The revised suite has 25 passing local pure/SSR/transport cases, including all-contact student projection, malicious redaction contradictions, own/assigned versus unassigned capabilities, protected-field omission, atomic prospect creation, lost assignment, and student recovery isolation.
- `tests/outreach-ui.spec.ts`: 17 authored Playwright tests cover 390/768/1440 layouts, overflow and readable heading widths, navigation/denial/backend-unavailable states, edits, Finance gating, late results, reload recovery, explicit cancellation, and sign-in deep links. Eight added student cases cover shared-contact portfolio/profile/history/form screenshots at all three sizes, prospect → contact → manual-email-log flow, student/lead navigation, unassigned read-only views, lost assignment while editing, omission of private/assignment fields, and fail-closed projection handling. Mentor screenshots retain their existing paths; student captures use `student-{portfolio,profile,history,editor}-{width}.png` in ignored `test-results/outreach-review/`. Modal captures are viewport-only with PNG dimension assertions.
- The pre-student draft passed its 441-test CI suite, and real synthetic captures were visually reviewed; the narrow phone/tablet heading fixes reached green draft head `c256591`. The new version-2 student capability changes require a fresh exact-head CI run and screenshot review. No local Chromium retry was made. Fixtures come only from `tests/fixtures/outreach.ts` and intercepted `.invalid` endpoints, with other HTTPS traffic blocked. Synthetic CI verifies UI behavior and layout, not authenticated production use.
- `npm run build` performs TypeScript checking and production bundling. It does not publish anything.

The UI reuses the current Hub navigation, session, fonts, colors, responsive shell, and Finance source of truth. There are no new production values or privileged client keys.
